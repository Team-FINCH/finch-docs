# Finch 화면 설계서 (기획, 와이어프레임)

- 문서 버전: v1.0
- 작성일: 2026-09-10
- 플랫폼: 모바일 웹 (반응형, 모바일 우선)
- UI 레퍼런스: 토스증권
- 원천 문서: `frontend/docs/ia.md` (화면 목록과 IA), `frontend/docs/design.md` (디자인 시스템), `docs/spec/featureSpec.md` v2.4 (기능 명세)
- 프로토타입: `prototype/screen/finch-prototype.html`, `prototype/screen/user-flow.html`

## 1. 이 문서의 위치

`ia.md` 는 프론트엔드가 **분담과 일정 산정**을 위해 쓰는 내부 문서다. 미확정 항목과 담당 묶음, 뒤집힌 전제의 이력이 함께 들어 있어 외부에서 읽기에는 잡음이 많다.

이 문서는 그 중에서 **화면 구조에 해당하는 것만** 뽑아 자립적으로 다시 적은 것이다. 값이 갈리면 `ia.md` 가 우선한다.

**구현된 라우터를 기준으로 적었다.** `ia.md` 가 `(미확정)` 으로 남겨 둔 라우트 세 개는 그 뒤 구현으로 확정됐고, 이 문서는 확정된 값을 쓴다 (§9 참고).

## 2. 설계 원칙

화면 구조를 결정한 규칙 다섯 가지다. 개별 화면의 생김새보다 이 규칙이 먼저다.

**1. 모바일 단일 컬럼과 하단 탭 바.** 데스크톱 전용 레이아웃을 만들지 않는다. 증권 앱을 실제로 쓰는 자리가 손안이고, 두 레이아웃을 유지하면 어느 쪽도 다듬어지지 않는다.

**2. 새로고침, 공유, 뒤로가기에서 살아 있어야 하는 것은 전부 URL 에 둔다.** 탭 선택과 정렬, 검색어를 컴포넌트 상태에 두면 뒤로가기 한 번에 사라진다. **모바일에서는 뒤로가기를 훨씬 자주 쓰므로 바로 티가 난다.** 예외는 주문 수량이다 — 공유될 값이 아니고, 공유되면 남의 주문 화면이 채워진 채 열린다.

**3. AI 는 독립 화면이 아니라 슬롯으로 들어간다.** 하단 탭에 `AI` 를 두지 않는다. 사용자가 "AI 를 쓰러" 가는 것이 아니라, 보고 있는 화면에 대해 묻는 것이기 때문이다. 그래서 AI 진입은 **화면 맥락을 물고 들어가는 플로팅 버튼**이다.

**4. 되돌리는 화면을 만들지 않는다.** 계좌 초기화 진입점과 회차 조회 화면을 뺐다 (GitLab 이슈 #27). 실제 투자 서비스에 없는 편의를 화면에 두면 연습용 도구로 읽힌다.

**5. 빈 상태는 오류가 아니다.** 잔고 0원, 보유 종목 없음, 검색 결과 없음은 **정상 초기 상태**다. 계좌가 0원으로 열리므로(기능명세 §2.2) 갓 가입한 사용자가 보는 첫 화면이 전부 빈 상태다. 여기에 오류 표시를 쓰면 서비스가 고장 난 것으로 읽힌다.

## 3. 화면 목록

전체 20개다. 라우트는 `frontend/src/shared/config/routes.ts` 의 값이다.

### 3.1 인증

| 화면 | 라우트 | 목적 | 진입점 |
|---|---|---|---|
| 로그인 | `/login` | 카카오 인가 화면으로 진입 | 미인증 접근, 로그아웃 |
| 카카오 콜백 | `/oauth/kakao` | 인가 코드를 토큰으로 교환 | 카카오 리다이렉트 |
| 온보딩 | `/onboarding` | 신규 사용자가 관심 종목을 고른다 | 콜백 (신규만) |

**자체 회원가입 폼이 없다.** 인증 수단은 카카오 OAuth 2.0 단일이고, 최초 로그인 시 서버가 계정과 계좌를 함께 만든다.

**온보딩은 신규 사용자에게만 열린다.** 다만 **로그인 전에 보려던 화면이 있으면 그곳이 우선이다** — 링크로 들어온 사람을 온보딩으로 끌고 가면 원래 보려던 것을 잃는다. 마치거나 건너뛰면 홈의 관심 종목 탭으로 보낸다.

**온보딩의 첫 행동을 매수가 아니라 관심 종목 담기로 뒀다.** 계좌가 0원이라 매수를 권할 수 없고, 관심 종목 하나만 담으면 데일리 브리핑이 켜져 다음에 들어올 이유가 생긴다.

**로그인 화면에 이용약관과 개인정보 처리방침 진입점이 있다.** 두 버튼이 바텀시트 하나를 공유하고 내용만 갈아 끼운다 (§7). 본문은 요약이고 시트 제목에도 "요약" 으로 표기한다 — **실제 법무 문안이 아니므로 서비스에 넣을 전문은 따로 받아야 한다.**

### 3.2 홈과 자산

| 화면 | 라우트 | 목적 | AI 슬롯 |
|---|---|---|---|
| 홈 | `/` | 총자산과 손익 요약, 보유 종목과 관심 종목 요약, 오늘의 브리핑 | 2종 |
| 포트폴리오 | `/portfolio` | 보유 종목 상세, AI 진단, 수익률 원인 분석, 투자 기준 4중 탭 | 2종 |
| 매매 내역 | `/transactions` | 원장 통합 내역 조회 (매수, 매도, 충전, 출금) | — |
| 브리핑 전체 | `/briefing` | 오늘의 브리핑 항목 전체 열람 | 1종 |
| 충전 | `/deposit` | 금액과 수단 입력, 결제 준비 | — |
| 모의 이체 | `/deposit/transfer` | `TRANSFER` 수단의 결제창 대역 | — |
| 충전 완료 | `/deposit/complete` | 카카오 승인 뒤 도착지. 충전을 확정한다 | — |
| 충전 실패 | `/deposit/fail` | 결제 실패 도착지 | — |
| 출금 | `/withdraw` | 예수금을 뺀다 | — |

**홈과 포트폴리오는 데이터 출처가 겹친다.** 같은 쿼리 키를 공유해 두 화면이 서로 다른 값을 보여주는 일이 없게 한다.

**포트폴리오는 탭 4개다** — 보유, AI 진단, 수익률 분석, 투자 기준. 넷째 탭이 위키(AI 가 이해한 나)이고, 이것은 원래 `/my/wiki` 독립 화면이었다가 2026-09-04 에 이 탭으로 합쳤다. **위키의 유일한 경로다.**

**관심 종목은 독립 화면을 갖지 않는다.** 홈 안의 영역으로만 존재한다. API 는 그대로 살아 있고 화면만 없앤 것이다 — 목록 하나만 있는 화면을 탭 하나로 두면 홈과 내용이 겹친다.

### 3.3 충전 흐름의 화면 네 개

충전이 화면 네 개를 쓰는 이유는 절차가 4단계이기 때문이다.

```
/deposit  ──►  결제창  ──►  승인  ──►  확정
  금액·수단      카카오 또는            /deposit/complete
  입력, 확인     /deposit/transfer      (실패는 /deposit/fail)
```

**준비와 확정이 나뉜 이유는 사용자의 브라우저가 결제창으로 떠났다가 돌아오기 때문이다.** 그동안 서버가 요청을 붙잡고 있을 수 없다.

**그래서 복귀 화면은 바텀시트로 만들 수 없다.** 외부 브라우저 이동에서 돌아오는 자리라 반드시 주소를 가져야 한다.

**예수금이 늘어나는 시점은 마지막 확정 하나뿐이다.** 화면은 승인 응답을 충전 성공으로 표시하지 않는다. 승인 뒤 확정 전에 사용자가 창을 닫으면 잔고는 그대로다.

**확정에서 막힌 건에는 재시도 버튼을 주지 않는다.** 금액 불일치나 한도 초과로 막히면 그 결제 건이 실패로 굳어 같은 건을 다시 확정할 수 없다. 처음부터 다시 하는 경로만 준다.

**모의 이체 화면에는 시나리오 선택이 있다.** 성공 외에 잔액 부족, 한도 초과, 타임아웃을 고를 수 있다. 시연에서 실패 흐름을 보여줄 수 있어야 하고, 실제 PG 를 일부러 실패시킬 방법이 없기 때문이다.

### 3.4 탐색과 거래

| 화면 | 라우트 | 목적 | AI 슬롯 |
|---|---|---|---|
| 종목 검색 | `/search` | 종목명과 코드로 찾기. 초기 상태가 최근 검색어와 **최근 본 종목**이다 | — |
| 종목 상세 | `/stocks/:stockCode` | 시세, 차트, 기업정보, AI 분석 | 1종 |
| 주문 | `/stocks/:stockCode/order` | 시장가 매수와 매도 | 1종 |

**최근 검색어는 별도 화면이 아니라 `/search` 의 초기 상태다.** 검색어를 지우면 다시 그 상태로 돌아온다. 화면을 나누면 사용자가 검색을 시작하려고 두 번 이동해야 한다.

**주문을 별도 라우트로 뒀다.** 바텀시트로 만들면 주문 확인 중에 뒤로가기를 눌렀을 때 종목 상세로 갈지 시트만 닫힐지가 애매해지고, 무엇보다 **주문 화면은 돈이 움직이는 자리라 주소가 있어야 재현과 공유가 된다.**

**차트 세그먼트의 축은 기간이 아니라 봉 종류다** — 일봉, 주봉, 월봉. 보이는 기간은 봉 개수가 정한다(일봉 60봉 약 3개월, 주봉 52봉 1년, 월봉 36봉 3년). 그래서 기간 탭을 따로 두지 않아도 3개월, 1년, 3년에 해당하는 화면이 그대로 나온다.

### 3.5 AI

| 화면 | 라우트 | 목적 | AI 슬롯 |
|---|---|---|---|
| AI 채팅 | `/chat` | Ask My Portfolio. 원장을 근거로 답한다 | 1종 |
| 알림함 | `/inbox` | AI 가 남긴 알림과 "적어야 할 것" | — |

**채팅은 `/chat` 전용 화면만이 아니다.** 값이 있는 화면에서 열면 화면 이름과 종목코드를 함께 실어 보낸다. 그래야 종목 상세에서 "이거" 가 그 종목으로 해소된다. **맥락 없이 열면 AI 가 되물어야 해서 대화가 한 번 더 왕복한다.**

### 3.6 기타

| 화면 | 라우트 | 목적 |
|---|---|---|
| 마이페이지 | `/my` | 프로필, 알림함과 위키와 매매 내역과 충전과 출금 진입, 로그아웃 |
| 상태 확인 | `/health` | 프론트가 백엔드와 AI 에 닿는지 확인 |
| 404 | `*` | 없는 경로 |

**설정 화면을 마이페이지로 흡수했다.** 테마와 로그아웃만 있는 화면을 따로 두면 사용자가 어느 쪽에 무엇이 있는지 외워야 한다.

## 4. 라우트 트리

```
/                              홈
/login                         로그인 (카카오 인가 진입)
/oauth/kakao                   카카오 콜백 (인가 코드 → 토큰 교환)
/onboarding                    온보딩 (신규 사용자만)
/search                        종목 검색 (초기 상태 = 최근 검색어 + 최근 본 종목)
/stocks/:stockCode             종목 상세
/stocks/:stockCode/order       주문
/portfolio                     포트폴리오 (탭 4개, 위키 포함)
/transactions                  매매 내역
/briefing                      브리핑 전체
/deposit                       충전
/deposit/transfer              모의 이체 (TRANSFER 결제창 대역)
/deposit/complete              충전 완료 (승인 복귀, 확정 수행)
/deposit/fail                  충전 실패 (승인 복귀)
/withdraw                      출금
/chat                          AI 채팅
/inbox                         알림함
/my                            마이페이지
/health                        상태 확인
*                              404
```

**종목코드 경로 파라미터는 `stockCode` 로 통일한다.** 백엔드 명세 전체가 `stockCode` 를 쓰고 AI 명세만 `ticker` 를 쓰는데, 프론트는 백엔드만 호출하므로 `stockCode` 를 따른다. **이름이 두 개면 파라미터 추출부에서 조용히 `undefined` 가 된다.**

**`/stocks/:stockCode` 와 `?tab=ai` 는 프론트 혼자 정하는 값이 아니다.** 브리핑 응답의 딥링크를 AI 서버가 이 경로 문자열로 직접 만들어 내려보낸다. **바꾸면 브리핑 링크가 조용히 404 가 된다** — 오류도 뜨지 않고 빈 페이지로 간다. 바꿔야 하면 AI 파트에 먼저 알린다.

## 5. URL 이 갖는 상태

| 경로 | 파라미터 | 값 |
|---|---|---|
| `/stocks/:stockCode` | `tab` | `chart` \| `info` \| `ai` |
| `/stocks/:stockCode` | `interval` | `DAY` \| `WEEK` \| `MONTH` |
| `/stocks/:stockCode` | `period` | `1M` \| `3M` \| `1Y` \| `3Y` |
| `/stocks/:stockCode/order` | `side` | `buy` \| `sell` |
| `/portfolio` | `tab` | `holdings` \| `diagnosis` \| `cause` \| `wiki` |
| `/portfolio` | `sort` | `EVALUATION` \| `PROFIT_RATE` |
| `/transactions` | `type` | `ALL` \| `BUY` \| `SELL` \| `DEPOSIT` \| `WITHDRAWAL` |
| `/search` | `q` | 검색어 |
| `/login` | `redirect` | 로그인 후 돌아갈 경로 |

`interval` 과 `period` 는 독립된 두 축이다 — `period` 는 얼마나 거슬러 올라가는지, `interval` 은 봉 하나가 며칠치인지다. **화면에 있는 탭은 `interval` 쪽 하나뿐이고**, 탭이 `interval` 을 고르면 짝이 되는 `period` 가 함께 실린다.

## 6. 화면 간 이동

### 6.1 하단 탭 바 — 4개

```
 홈        탐색        포트폴리오      내 정보
 /         /search     /portfolio     /my
```

**`AI` 탭이 없다.** §2 원칙 3 의 결과다. 그 자리에 `내 정보` 가 들어왔다.

### 6.2 AI 플로팅 버튼

탭 바 위에 떠 있고, **화면 맥락을 물고 `/chat` 으로 들어간다.** 종목 상세에서는 문구가 "이 종목 물어보기" 로 바뀐다.

배치는 종목 상세, 포트폴리오, 브리핑, 뉴스 상세다. 바텀시트가 열려 있으면 숨는다 — 시트 위에 뜨면 시트의 확인 버튼을 가린다.

### 6.3 주요 흐름

**최초 진입**

```
/login ──► 카카오 인가 ──► /oauth/kakao ──► /onboarding ──► /?list=watch
                                       └──► (기존 사용자) / 또는 원래 가려던 경로
```

**매수**

```
/search ──► /stocks/:code ──► /stocks/:code/order?side=buy ──► 확인 ──► 체결
                                                                        │
                                                          매수 이유 기록 시트
```

체결 직후 **"왜 담으셨나요?" 시트**가 뜬다. 이 기록이 나중에 AI 의 투자 논지 점검(위키)의 재료가 된다. 지금 적지 않으면 나중에 기억으로 복원해야 하고, 그건 사실이 아니라 사후 해석이 된다.

**예수금 부족**

```
주문 ──► 예수금 부족 ──► "충전하기" ──► /deposit ──► 결제창 ──► /deposit/complete
```

**충전은 매매의 시작점이다.** 계좌가 0원으로 열리므로 신규 사용자의 첫 흐름이 이것이다.

## 7. 바텀시트

**상태값은 6개이고 실제로 그려지는 템플릿은 5개다** — 이용약관과 개인정보 처리방침이 템플릿 하나를 공유한다.

| 상태값 | 내용 | 여는 곳 |
|---|---|---|
| `terms` | 이용약관 요약 | 로그인 화면 하단 |
| `privacy` | 개인정보 처리방침 요약 (`terms` 와 템플릿 공유) | 로그인 화면 하단 |
| `term` | 금융 용어 설명 (PER, PBR 등) | 종목 상세의 지표 라벨 |
| `record` | 매수 이유 기록 입력 | 매수 체결 직후, 알림함의 "적어야 할 것" |
| `delfact` | 위키 사실 삭제 확인 | 포트폴리오 위키 탭 |
| `insight` | AI 종목 분석 상세 | 종목 상세의 AI 분석 미리보기 카드 |

**`terms` 와 `term` 은 이름만 비슷하고 다른 시트다.** 앞은 이용약관, 뒤는 금융 용어 설명이다.

**시트로 만든 것과 라우트로 만든 것의 경계**는 이렇다. 뒤로가기로 닫히는 것이 자연스럽고 공유될 필요가 없으면 시트, 외부에서 돌아오거나 주소가 필요하면 라우트다. 주문과 결제 복귀가 라우트인 이유가 그것이다 (§3.3, §3.4).

## 8. AI 슬롯 배치

AI 기능 6종이 화면에 들어가는 자리다. **기능 6개와 슬롯 6종이 1:1 은 아니다** — 하나가 여러 화면에 나오고, 한 화면이 여럿을 담는다.

| AI 기능 | 들어가는 화면 |
|---|---|
| 종목 분석 | 종목 상세 (`?tab=ai`, 미리보기 카드 + `insight` 시트) |
| Ask My Portfolio | `/chat` (플로팅 버튼으로 맥락과 함께 진입) |
| 포트폴리오 진단 | 포트폴리오 `?tab=diagnosis` |
| 수익률 원인 분석 | 홈, 포트폴리오 `?tab=cause` |
| 주문 전 점검 | 주문 |
| 데일리 브리핑 | 홈 (요약), `/briefing` (전체) |

**보조 슬롯 둘.** 응답 피드백은 AI 답변이 나오는 자리마다 붙고, 사용자 컨텍스트(위키)는 포트폴리오 넷째 탭이다.

**근거 표시 규칙.** AI 서술은 근거를 함께 받지만 **각주 표기(`[^cit_2]`)를 화면에 내지 않는다.** 번호로도 뱃지로도 그리지 않고 걷어낸다 — 각주를 눌러 갈 목록이 화면에 없기 때문이다. 근거는 별도 영역에서 보여준다.

**AI 는 매매를 권유하지 않는다.** 포트폴리오 진단과 주문 전 점검은 위험 지표를 제시하는 것까지만 하고, 리밸런싱 제안이나 목표주가는 화면에 두지 않는다. 규제 리스크 때문에 MVP 와 확장 모두에서 제외한 항목이다 (기능명세 §10.2).

## 9. 구현 현황

`frontend/src/app/router.tsx` 와 `routes.ts` 를 대조한 결과다 (2026-09-10).

| 항목 | 결과 |
|---|---|
| 라우트 정의 | 19개 + 404 캐치올 |
| 실제 페이지 컴포넌트에 연결 | **19개 전부** |
| `RoutePlaceholder` | **0개.** 컴포넌트 자체를 지웠다 |

**`/recent` 전용 화면은 만들지 않기로 확정했다** (2026-09-17, `89d9359`). 최근 본 종목은 탐색 화면(`/search`)의 초기 상태에 최근 검색어와 나란히 있어 같은 목록을 두 화면에 둘 이유가 없었고, 자리표시자 화면에는 탭 바도 뒤로가기도 없어 **들어가면 나올 길이 없었다.**

라우트, 링크, `ROUTES.recent` 상수, `RoutePlaceholder` 컴포넌트를 함께 지웠다. API(`GET/DELETE /api/v1/stocks/recent`)는 탐색 화면이 그대로 쓴다.

### `ia.md` 와 달라진 것

`ia.md` 가 `(미확정)` 또는 `(잠정)` 으로 남긴 라우트가 그 뒤 구현으로 확정됐다. 이 문서는 확정값을 쓴다.

| `ia.md` 표기 | 확정된 라우트 |
|---|---|
| 결제 복귀 (미확정, P23) | `/deposit/complete`, `/deposit/fail` |
| 모의 이체 (미확정, P24) | `/deposit/transfer` |
| 브리핑 전체 (미확정) | `/briefing` |

`ia.md` 에 없고 구현에만 있는 것이 하나 있다 — `/health` 다. 프론트가 백엔드와 AI 에 닿는지 확인하는 화면이고 사용자 대면 기능이 아니다.

`ia.md` 는 화면을 19개로 세는데 이 문서는 20개다. 세는 방식이 달라서다 — `ia.md` 는 최근 검색어를 `/search` 의 상태로 세고 `/health` 를 빼고 404 를 넣는다. **같은 화면 집합이고 집계 기준만 다르다.**

## 10. 화면 공통 규약

**빈 상태.** 잔고 0원, 보유 없음, 검색 결과 없음, 관심 종목 없음은 정상 상태로 그린다. 오류 색과 경고 아이콘을 쓰지 않고, 다음에 할 행동을 하나 제시한다 (충전하기, 종목 찾기).

**로딩.** AI 응답은 수 초가 걸린다. 스켈레톤으로 자리를 잡아 화면이 밀리지 않게 하고, **응답 대기 중에도 나머지 화면은 조작할 수 있게 둔다.**

**오류.** 사용자가 할 수 있는 행동을 문구에 넣는다. "예수금이 부족합니다" 에는 충전 진입을, "지금은 주문할 수 없어요" 에는 거래 시간을 함께 적는다.

**금액과 등락.** 원화, 천 단위 콤마. 상승 빨강, 하락 파랑 (국내 관행).

**서버 값을 다시 계산하지 않는다.** 잔고, 손익, 수익률은 원장에서 계산한 서버 값을 그대로 쓴다. 화면이 재계산하면 같은 값이 두 곳에서 다르게 보이는 순간이 생긴다.
