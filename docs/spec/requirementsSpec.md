# Finch 요구사항 명세서

- 문서 버전: v1.0
- 작성일: 2026-09-10
- 대상 릴리스: MVP (기능 동결 2026-09-23, 발표 2026-09-28)
- 상위 문서: `docs/spec/featureSpec.md` v2.4 (기능 명세서)
- 연계 문서: `docs/api/apiSpec.md` (백엔드 API), `docs/api/aiApiSpec.md` (AI 서비스 API), `docs/erd/erd.md` (ERD)

## 1. 문서 개요

### 1.1 목적

이 문서는 Finch 가 **무엇을 만족해야 하는지**를 검증 가능한 단위로 쪼개 적는다. 기능 명세서(`featureSpec.md`)가 화면과 정책을 서술형으로 정하는 문서라면, 이 문서는 그것을 **요구사항 ID 단위로 나누어 판정 기준과 현재 상태를 붙인** 문서다.

두 문서가 갈리면 **`featureSpec.md` 가 우선한다.** 이 문서는 그것의 파생물이다.

### 1.2 제품 정의

Finch 는 실제 시세로 돌아가는 **모의투자 서비스**다. 실제 금전 이동 없이 가상 예수금으로 국내 상장 종목을 매매하고, 그 결과를 AI 가 사용자의 원장과 시장 데이터에 근거해 설명한다.

**핵심 성격 세 가지가 요구사항 전반을 결정한다.**

1. **원장이 단일 진실 공급원이다.** 잔고, 손익, 수익률은 저장된 값이 아니라 원장에서 계산한 값이다. 클라이언트 계산값을 신뢰하지 않는다.
2. **AI 는 원장을 쓰지 않는다.** 읽기 전용 계약으로만 접근한다. AI 가 잔고를 바꿀 경로는 존재하지 않는다.
3. **되돌리는 기능을 넣지 않는다.** 계좌 초기화도, 충전 취소도 없다. 실제 투자 서비스에 없는 편의를 넣으면 연습용 도구로 읽힌다.

### 1.3 용어

`featureSpec.md` §0 을 그대로 따른다. 이 문서에서 추가로 쓰는 용어만 적는다.

| 용어 | 정의 |
|---|---|
| 요구사항 ID | `FR-<영역>-<번호>` (기능), `NFR-<번호>` (비기능), `EIF-<번호>` (외부 인터페이스) |
| 판정 기준 | 그 요구사항이 충족됐는지 사람이 확인할 수 있는 조건 |
| MVP 필수 | 이것이 빠지면 시연 시나리오가 성립하지 않는 요구사항 |
| 확장 | MVP 이후. 이 문서는 범위 경계를 밝히기 위해서만 적는다 |

### 1.4 이해관계자와 담당

| 파트 | 담당 범위 |
|---|---|
| Frontend | 화면, 라우팅, 상태 관리, 목 서버(MSW) |
| Backend | 원장, 인증, 시세 중계, AI 중계, 외부 결제 연동 |
| AI | 분석 생성, RAG 검색, 근거 데이터 적재, 가드레일 |
| Infra | 서버, 컨테이너, CI/CD, 쿠버네티스, 관측, 배치 스케줄 |

파트 디렉터리 소유권은 ADR-0002 를 따른다. 다른 파트의 디렉터리를 직접 수정하지 않는다.

## 2. 시스템 개요

### 2.1 구성

```
 사용자 브라우저
      │  HTTPS 443
      ▼
   nginx  ──────────────────────────────┐
      │  /            정적 파일 (SPA)   │  /jenkins  → Jenkins
      │  /api         → backend         │
      ▼                                 │
  backend (Spring Boot)                  │
      │                                  │
      ├── PostgreSQL (원장, 계정, 종목)   │
      ├── Redis (멱등성 키, 캐시)        │
      ├── 외부 API (카카오, 카카오페이, 한국투자증권)
      │                                  │
      └── AI 중계 → ai (FastAPI)         │
                        │                │
                        ├── PostgreSQL + pgvector (문서, 임베딩, 시세)
                        └── 외부 API (GMS, DART, KRX, ECOS, 네이버)
```

**프론트는 AI 서버를 직접 호출하지 않는다.** 모든 AI 호출은 백엔드가 중계한다. 인증 주체를 하나로 두고, AI 서버를 외부에 노출하지 않기 위해서다.

### 2.2 배포 형태

MVP 는 **단일 서버(EC2)** 에 올린다. 현재 두 가지 형태가 함께 존재한다.

| 형태 | 용도 | 구성 |
|---|---|---|
| **k3s (쿠버네티스)** | **운영. 2026-09-11 커트오버 완료** | `finch` 네임스페이스(앱) + `finch-observability`(관측) |
| Docker Compose | 롤백 경로. Jenkins 와 gitlab-runner 는 클러스터 밖 compose 에 남는다 | nginx, backend, ai, PostgreSQL 2개, Redis |

배포는 Helm 이다. Jenkins 가 master 머지마다 변경 파트를 감지해 이미지를 빌드하고
`helm upgrade --install finch ... --atomic` 으로 올린다 (`Jenkinsfile:193`).
이미지 태그는 `latest` 가 아니라 **그 파트를 마지막으로 건드린 커밋 해시**다.

트래픽은 Cloudflare Tunnel 이 받아 k3s Ingress(nginx)로 넘긴다. 서비스 주소는
`finchapp.org` 이고, 지급받은 `finchapp.org` 도 같은 서비스를 계속 받는다.

## 3. 구현 상태 판정 근거

이 문서의 **구현 상태 열은 추정이 아니라 측정 결과다.** 방법을 밝혀 두어 누구든 다시 확인할 수 있게 한다.

### 3.1 API 는 실제 서버에 요청해 확인했다

`docs/api/apiSpec.md` 에 적힌 39개 엔드포인트 전부에 요청을 보내 응답 코드를 봤다 (2026-09-10 측정).

```
while read -r m p; do
  u=$(printf '%s' "$p" | sed -e 's/{stockCode}/005930/' -e 's/{paymentId}/1/' \
                              -e 's/{factId}/1/'    -e 's/{keywordId}/1/')
  printf '%-6s %-46s %s\n' "$m" "$p" \
    "$(curl -s -o /dev/null -w '%{http_code}' -X "$m" "https://finchapp.org$u")"
done < endpoints.txt
```

결과는 **401 이 37건, 400 이 2건, 404 는 0건**이다. 404 가 없다는 것이 판정의 핵심이다 — 라우트가 없으면 Spring 이 404 를 낸다. 401 은 핸들러까지 도달해 인증에서 막힌 것이므로 **그 엔드포인트가 구현되어 배포돼 있다는 증거다.**

400 두 건은 `POST /api/v1/auth/kakao` 와 `GET /api/v1/deposits/kakao/approval` 로, 인증 없이 부를 수 있으나 필수 파라미터가 없어 거부된 것이다. 역시 라우트 존재를 뜻한다.

AI 서비스는 컨테이너의 OpenAPI 문서를 직접 읽어 확인했다.

```
docker exec finch-ai python -c "import urllib.request,json; \
  print(sorted(json.load(urllib.request.urlopen('http://localhost:8000/openapi.json'))['paths']))"
```

`/api/ai/v1` 아래 11개 라우트와 `/health` 가 떠 있다.

### 3.2 화면은 라우터 정의로 확인했다

`frontend/src/app/router.tsx` 와 `frontend/src/shared/config/routes.ts` 를 대조했다. **라우트 19개가 전부 실제 페이지 컴포넌트에 연결돼 있다.** 자리표시자는 하나도 없다 — `RoutePlaceholder` 컴포넌트 자체가 2026-09-17 에 삭제됐다. 여기에 404 라우트가 하나 더 있다.

관심 종목은 별도 라우트가 없다. `HomePage` 안의 요약 목록과 온보딩 화면에서 처리한다 — 화면이 없는 것이 아니라 홈에 포함된 형태다.

### 3.3 Jira 상태는 근거로 쓰지 않았다

Jira 는 완료 156건, 미완료 60건이다. 그런데 **이 숫자는 구현 상태와 맞지 않는다.**

예를 들어 `FINCH-47`(매매 내역, 잔고 조회 API)과 `FINCH-144`(transactions)는 "해야 할 일" 인데 `GET /api/v1/transactions` 와 `GET /api/v1/portfolio` 는 실제로 배포돼 있다. 티켓을 닫지 않은 것이다. 반대로 `FINCH-53`(투자 회차)은 열려 있지만 v2.2 에서 **범위에서 제거된 기능**이다.

그래서 이 문서는 Jira 를 참고 정보로만 두고, 판정은 3.1 과 3.2 로 한다.

### 3.4 이 문서가 보증하지 않는 것

**구현 상태는 "존재" 이고 "정상 동작" 이 아니다.** 엔드포인트가 401 을 낸다는 것은 라우트와 인증 필터가 있다는 뜻이고, 그 안의 계산이 맞다는 뜻은 아니다. 동작 검증은 테스트 계획/결과 문서의 몫이다.

표기는 아래 셋만 쓴다.

| 표기 | 뜻 |
|---|---|
| 구현 | API 가 배포돼 있고(3.1) 또는 화면이 컴포넌트에 연결돼 있다(3.2) |
| 구현, 미가동 | 코드는 master 에 있고 서버에도 올라갔으나 **설정이 빠져 실제로는 동작하지 않는다** |
| 자리표시자 | 라우트는 있으나 `RoutePlaceholder` 다 |
| 미구현 | 위 어느 것도 아니다 |

**`구현, 미가동` 을 별도 표기로 둔 이유가 있다.** 코드가 머지된 것과 그 기능이 실제로 도는 것은 다르다. 알림처럼 외부 설정값(웹훅 URL)이 필요한 기능은 코드만 보면 완성으로 읽히는데, 설정이 없으면 **조용히 건너뛴다.** 문서가 그것을 완료로 적으면 아무도 확인하지 않는다.

**NFR-06 과 NFR-07 은 비용 통제 장치다.** LLM 은 호출당 비용이 있고, 가드레일 반려 시 재시도가 붙어 한 요청이 여러 번의 호출이 된다. 상한이 없으면 발표 전에 예산이 마르고, 그때는 기능이 조용히 실패한다.

**NFR-08, NFR-09 는 미구현이다** (`FINCH-58`, `-59`, `-62`). 시연 규모에서는 드러나지 않을 수 있으나, 자원 상한을 추정으로 둔 상태라 남은 기간에 실측이 필요하다.

## 6. 외부 인터페이스 요구사항 (EIF)

환경변수 계약(`infra/.env.example`, `ai/.env.example`)에 정의된 연동 8종이다.

| ID | 외부 서비스 | 용도 | 실패 시 영향 | 우선순위 | 상태 |
|---|---|---|---|---|---|
| EIF-01 | 카카오 OAuth 2.0 | 로그인 | **로그인 불가.** 서비스 진입 자체가 막힌다 | MVP필수 | 구현 |
| EIF-02 | 카카오페이 (테스트 CID) | 예수금 충전 | 충전 불가. 계좌이체 모의 경로로 우회 가능 | MVP필수 | 구현 |
| EIF-03 | 한국투자증권 OpenAPI | 시세, 종목 정보 | 현재가와 차트가 비고 주문이 제한된다 | MVP필수 | 구현 |
| EIF-04 | GMS (OpenAI 호환 게이트웨이) | LLM 추론, 임베딩 | AI 기능 6종 전부 실패 | MVP필수 | 구현 |
| EIF-05 | DART 전자공시 | 공시 원문 적재 | AI 분석의 공시 근거가 빈다 | MVP | 구현 |
| EIF-06 | KRX 정보데이터시스템 | 시가총액, 지수 | 시장 대비 비교(수익률 원인 분석)가 빈다 | MVP | 구현 |
| EIF-07 | 한국은행 ECOS | 거시 지표 | AI 분석의 거시 근거가 빈다 | MVP | 구현 |
| EIF-08 | 네이버 검색 | 뉴스 수집 | AI 분석의 뉴스 근거가 빈다 | MVP | 구현 |

**외부 호출 구조 원칙.** 앱키를 팀이 공유하면 호출 제한도 공유된다. 각 서비스가 개별 호출하지 않고 **중앙에서 한 번 호출해 내부로 배포한다.** 호출 제한이 앱키 단위이므로 필요하면 키를 풀로 들고 종목을 나눠 호출할 수 있게 설계한다.

**EIF-01 과 EIF-04 는 단일 실패점이다.** 카카오 OAuth 가 죽으면 아무도 들어올 수 없고, GMS 가 죽으면 AI 기능이 전부 멈춘다. 시세 쪽은 NFR-22 로 막았지만 — 값이 낡으면 주문을 거절한다 — **AI 쪽은 막을 수단이 없다.** 생성이 실패하면 화면이 안내 문구로 대체될 뿐이다.

## 7. 범위 제외

의도적으로 만들지 않는 것이다. **못 만든 것과 구분한다.**

| 항목 | 제외 이유 |
|---|---|
| 계좌 초기화, 투자 회차 | 실제 투자 서비스에 없다. 손실을 되돌릴 수 없는 것이 실제 투자의 성질이고, 되돌릴 수 있게 만들면 연습용 도구로 읽힌다 |
| 충전 취소 | 충전금이 다른 현금과 섞여 사용 여부를 추적할 수 없다. 건별 추적 설계가 선행돼야 한다 |
| 초기 예수금 지급 | 실제 증권 서비스가 가입만으로 돈을 주지 않는다. 설정값(`finch.account.initial-cash`)으로 남겨 두어 되살릴 수는 있다 |
| 회원 탈퇴 | MVP 범위 밖 |
| 지정가 주문, 미체결 관리 | 체결 감시 워커 설계가 선행돼야 한다 |
| 포트폴리오 전체 수익률 | 원금(누적 충전액) 정의가 확정되지 않았다 |
| 리밸런싱 제안, 목표주가, 애널리스트 컨센서스 | **규제 리스크.** 특정 매매 권유는 투자자문에 해당할 수 있다 (FR-AI-14) |
| 종목 순위 (거래량, 등락률) | 외부 원천의 순위 API 제공 여부에 달려 있다 |
| 수수료와 세금 | 모의 서비스에서 계산 복잡도만 늘고 학습 가치가 없다 |

### 8.3 미충족 요구사항 요약

| ID | 요구사항 | 관련 티켓 | 판단 |
|---|---|---|---|
| NFR-08 | 부하 측정 | FINCH-58, 62 | 시연 규모에서는 드러나지 않을 수 있다 |
| NFR-09 | 자원 상한 실측 | FINCH-59 | 현재 상한은 추정값이다 |
| NFR-18 | 배치 실패 알림 | FINCH-216 | **구현, 미가동.** `notify-lib.sh` 는 서버에 있으나 `/etc/finch/notify-webhook` 가 없어 알림이 건너뛰어진다 |
| NFR-19 | AI 적재 경보 | FINCH-187 | **구현, 미가동.** 차트는 master 에 있으나 관측 차트가 배포되지 않았고 `alert-webhook` Secret 도 없다 |

**남은 기간의 우선순위는 NFR-18, NFR-19(배치 실패와 적재 경보)다.** 코드는 있는데 `/etc/finch/notify-webhook` 이 없어 알림이 조용히 건너뛰어진다 — 시연 중 적재가 실패해도 아무도 모르는 상태다. 파일 하나를 놓으면 둘 다 살아난다.

**NFR-18 과 NFR-19 는 코드가 아니라 설정이 남았다.** 웹훅 URL 을 `/etc/finch/notify-webhook` (600 root) 에 넣고, 그 파일로 쿠버네티스 Secret 을 만들면 둘이 함께 살아난다. URL 은 시크릿이라 저장소나 문서에 적지 않는다.

```
sudo install -m 600 /dev/null /etc/finch/notify-webhook   # 편집기로 URL 입력
kubectl -n finch-observability create secret generic alert-webhook   --from-file=url=/etc/finch/notify-webhook
```
